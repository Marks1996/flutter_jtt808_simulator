# 可视化建线与驾车路径规划

更新：2026-10-30。中国大陆新工作区默认使用天地图官方底图和高德驾车规划，需分别填写自有 Key；OSRM 作为可选自建服务，默认地址留空，已有配置不覆盖。见 [CHINA_ACCESS.md](CHINA_ACCESS.md)。底图与路径规划独立配置。本功能用于 JT808 模拟回放，不提供实时导航、限行保证或真实驾驶建议。

## 操作流程

1. 在「设置 → 路径规划」选择 OSRM 或高德，填写自己的服务配置，点击「应用路径规划配置」。修改设置不会发起规划请求，也不会改写已保存线路。
2. 在「线路与任务 → 新增线路」填写名称。新线路默认打开「地图建线」；仍可切换到「CSV 坐标」使用原有导入流程。
3. 按行驶顺序点击地图，或输入 `纬度,经度` 的 WGS84 坐标。首个点是起点，最后一个点是终点，中间为途经点。应用最多接受 18 个点（起终点加 16 个途经点），服务账号或自建服务可能有更低限制。
4. 点击编号标记或列表项选中某点，再点击地图或输入坐标替换位置。列表支持向前、向后移动及删除，也可以清空选点。右上角按钮可缩放至全部选点。
5. 设置 1–200 km/h 的模拟回放速度，点击「规划驾车线路」。**只有此操作发送规划请求**；点击地图、调整选点、切换页签及保存已有结果都不会自动调用规划服务。
6. 应用使用服务返回的第一条驾车线路，将完整几何转换为 WGS84 并填入 CSV。确认蓝线和轨迹点数、距离后，点击「保存线路」。回放使用设定速度，不使用规划服务的交通速度或预计到达时间。
7. 规划线路会随工作区保存原始选点及服务名称，重新编辑时可继续调整，而不是把每个道路几何顶点当作途经点。CSV 导出只包含 WGS84 轨迹，不包含服务凭证和选点元数据；直接修改 CSV 后清除规划来源标记。

修改选点或规划设置会使当前规划失效，并取消进行中的请求；旧请求即使迟到，也不会覆盖新结果。取消规划、网络失败、无可行路线及超出点数限制时保留选点，不自动用起终点直线冒充道路。未经重新规划的选点不能作为有效规划保存。若明确改用 CSV，可编辑并验证 CSV 后保存。

编辑器取消、关闭、Escape 和点击遮罩均沿用未保存修改保护；存在运行或暂停中的关联任务时，需先停止任务再修改线路。底图关闭或失败时地图仍可交互，也可输入 WGS84 坐标；空白坐标地图本身不包含道路数据。

## OSRM

设置页提供「公共 OSRM · 免 Key」和「FOSSGIS OSRM · 免 Key」两个一键填入入口，应用后可直接请求驾车路线，无需 Key。两个地址仍可编辑，选择按钮不自动提交或发起请求。已在本机直连获得北京完整 GeoJSON 响应，但不代表所有大陆网络可达。具体 URL、政策与检查记录见 [KEYLESS_SERVICES.md](KEYLESS_SERVICES.md)。

- 接口为 `{服务基础地址}/route/v1/driving/{经度,纬度;…}`，使用 `overview=full`、`geometries=geojson`、`steps=false`、`alternatives=false`。按输入选点顺序规划，不做途经点顺序优化。
- OSRM 基础地址默认留空，需填写自己的服务。曾经使用的 `https://router.project-osrm.org` 公共演示地址不再自动填入，但显式保存的旧值保留。该服务不保证中国大陆可达，也没有生产可用性保证，禁止过量调用。应用仅接受手动规划，对两个公共入口合并增加至少一秒的请求间隔且同时只允许一个在途公共请求，不自动重试；应用限制不能代替服务政策或部署方的总量控制。
- 正式联调宜配置自建服务或有服务合同的端点。服务基础地址可带反向代理前缀，但不要填写 `/route/v1/driving`、查询参数、账号密码或片段。支持 HTTPS；HTTP 仅限 `localhost`、`127.0.0.1` 和 `::1`，例如 `http://127.0.0.1:5000`。远程或局域网服务应配置 HTTPS。
- `driving` 路径名称并不能证明服务加载的是驾车路网；自建方必须以正确车辆 profile 准备覆盖目标地区的地图数据。国内覆盖、道路新旧、交通限制和可用性取决于部署数据。
- 返回坐标按 WGS84 解释。应用只保留有效、相邻不重复的几何点，不静默截断或简化；超过 10000 点会报错，需缩短线路。
- 请求携带应用 User-Agent。界面显示 OSRM 及公共演示 OpenStreetMap 数据来源；自建服务的数据来源、ODbL 等许可和额外归属由部署方确认。

## 高德官方驾车规划

- 接口为 `https://restapi.amap.com/v5/direction/driving`，使用 Web 服务 Key、`strategy=32`（高德推荐）、`show_fields=polyline`。按顺序拼接第一条路线的 `route.paths[0].steps[].polyline`，去除相邻重复端点。
- 请求前将 WGS84 选点近似转换为 GCJ-02；返回几何近似转换为 WGS84 后保存，不把 GCJ-02 当作 GPS 数据。转换不是供应商官方坐标转换接口，不能用于测绘精度或真实道路导航保证。
- 官方文档写明途经点**默认支持 1 个、最多 16 个**，实际账号权限应向供应商确认。应用的 18 点上限不表示普通 Key 已获得全部途经点权限。
- Key 必须为具有相应权限的 Web 服务 Key，非 JS 或移动 SDK Key。本客户端没有数字签名功能；要求签名的账号配置目前不适用。还应检查账号配额、IP 白名单和商业许可。
- 高德公开条款涉及缓存、存储、下载和脱离服务使用等限制。**普通 Key 或底图瓦片授权不能证明允许本工具的全部用途**：第三方地图引擎/底图展示、WGS84 转换、本地持久化、CSV/JSON 导出、离线回放及 JT808 模拟发送。需获得覆盖这些用途的授权；设置中确认后才能发起高德规划。该确认仅是操作者声明，不是本项目提供的法律授权。
- 暂未接入百度路径规划；百度仍可作为已有的授权底图选项使用。

## 存储、隐私与错误处理

- 保存的线路、选点、CSV/JSON、里程计算、回放与 JT808 报文使用 WGS84。地图的 GCJ-02/BD-09 显示和服务坐标转换均在边界处理；CSV 输入仍必须声明 `# WGS84`，不会自动猜测坐标系。
- 规划服务会获得 IP、选点与必要的 API 参数；不附加终端手机号、车牌或鉴权码。打开地图编辑器会按查看范围加载所选底图，即使还没有选点；关闭在线底图可停止后续瓦片请求，但不阻止用户明确发起的规划请求。
- 路径规划 Key、OSRM 地址和授权确认随工作区以明文保存、导入和导出。分享 JSON 前删除敏感配置；线路自身的规划元数据不含 Key。
- 使用项目共用 Dio 客户端，通过领域接口隔离服务。规划请求跳过包含 URL 的 HTTP 诊断日志，错误仅保留分类，不将带坐标/Key 的原始 Dio 异常或供应商响应抛到界面与应用日志。请求不跟随重定向。
- 无可行路线、坐标无效、接口格式不兼容、账号权限/配额不足与网络超时均有恢复提示。当前最多 10000 个几何点；没有自动把长线路截短，没有把失败请求视为成功。
